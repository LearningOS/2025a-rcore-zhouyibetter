## Essay Question

1. PageTableEntry由物理页帧号和标志位组成  
    非叶节点（页目录表，非末级页表）的表项标志位含义和叶节点（页表，末级页表）相比有一些不同：
        - 当 V 为 0 的时候，代表当前指针是一个空指针，无法走向下一级节点，即该页表项对应的虚拟地址范围是无效的；
        - 只有当 V 为1 且 R/W/X 均为 0 时，表示是一个合法的页目录表项，其包含的指针会指向下一级的页表；
        - 注意: 当 V 为1 且 R/W/X 不全为 0 时，表示是一个合法的页表项，其包含了虚地址对应的物理页号。

2. 缺页  
    1. 在 RISC-V 架构中，缺页异常通常表现为以下三种异常类型，这些异常可能由缺页导致：
        - 指令页错误（Instruction Page Fault）：异常代码为 12，当 CPU 尝试从无效的页面获取指令时触发。
        - 加载页错误（Load Page Fault）：异常代码为 13，当加载指令（如 load 操作）访问无效页面时触发。
        - 存储页错误（Store Page Fault）：异常代码为 15，当存储指令（如 store 操作）访问无效页面时触发。

    2. 当缺页异常发生时，RISC-V 架构中以下寄存器会被设置，以提供异常信息：
        - scause 寄存器：存储异常原因代码，例如 12、13 或 15，对应上述缺页异常类型。
        - stval 寄存器：存储导致缺页的虚拟地址（故障地址）。
        - sepc 寄存器：存储发生异常时的程序计数器（PC）值，即导致缺页的指令地址。
        - sstatus 寄存器：包含处理器状态信息，如之前的权限模式（U-mode 或 S-mode），其中 SPP 字段指示异常发生前的模式。

    3. Lazy 策略（延迟分配）在内存管理中有以下好处：  
        - 减少不必要的内存分配：如果进程申请了大量内存但只使用一小部分，OS 不会立即分配所有物理内存，避免了资源浪费。
        - 提高启动速度：对于程序加载，OS 延迟从磁盘加载代码或数据，只在实际访问时加载，减少了初始 I/O 操作，加快程序启动。
        - 降低开销：减少了页表操作和物理内存分配的次数，提高了系统整体效率。
        - 例如，在问题场景中，进程申请 10G 内存但只使用 1M，Lazy 策略避免了为未使用的 9.99G 内存建立页表映射和分配物理内存，节省了大量操作。

    4. 处理 10G 连续的内存页面，SV39 页表占用内存的估算 10MB

    5. 实现 Lazy 策略的简单思路：  
        - 当进程申请内存（如 mmap）时，OS 不立即分配物理内存或建立页表映射，而是将页表项标记为无效（Valid bit 为 0），并记录该内存区域的元数据（如大小、磁盘位置、权限等）。
        - 当进程首次访问该内存时，触发缺页异常。

        **缺页处理步骤**：
        1. OS 在异常处理程序中，读取 scause 和 stval 寄存器，确定异常类型和故障地址。
        2. 检查故障地址是否在 Lazy 分配的区域中（通过进程的 VMA 列表或其他数据结构）。
        3. 如果合法，则分配物理页帧，并更新页表项，设置 Valid bit 为 1 并填充物理帧号。
        4. 如果需要从磁盘加载数据（如代码段），则进行 I/O 操作。
        5. 恢复现场，重新执行导致异常的指令（通过 sepc）。
        6. 如果地址非法，则终止进程。
        7. 这种方法确保了内存按需分配，减少了初始开销。

    6. Swap 策略下页面失效在页表项上的表现  
    在 Swap 策略中，当物理内存不足时，OS 将部分页面换出到磁盘，此时页表项（PTE）会表现为：
        - Valid bit（第 0 位）为 0：表示页面无效，访问时会触发缺页异常。
        - PTE 的其他位用于存储交换信息：例如，在 RISC-V 的 PTE 格式中，第 63-10 位是保留给 OS 使用的，可以存储页面在磁盘上的位置（如交换分区索引扇区号）。这些位在 Valid bit 为 0 时不被 MMU 解释，但 OS 可以在缺页处理中读取它们以定位磁盘上的页面。

        当缺页发生时，OS 根据 PTE 中的交换信息，将页面从磁盘换入内存，更新 PTE 的 Valid bit 为 1 并设置物理帧号，然后重新执行指令。

3. 单/双页表  
    1. 在单页表设计中，每个进程只有一张页表，同时映射用户空间和内核空间。更换页表的情况相对简单：

    - 进程切换时：当从一个用户进程切换到另一个用户进程时，需要将 satp 寄存器更新为新进程的页表物理地址。
    - 进入/退出内核时：不需要更换页表，因为内核和用户空间在同一张页表中。
    ```asm
    # 进程切换时更换页表
    csrw satp, new_process_page_table
    sfence.vma
    ```
    2. 单页表情况下如何控制用户态无法访问内核页面？
    通过页表项(PTE)的权限位来控制：
    - U位(User位)：表示该页面是否允许用户态访问
        - U=1：用户态可以访问
        - U=0：只有特权模式(S-mode/M-mode)可以访问

        内核空间的页表项都设置 U=0，这样当CPU在用户态(U-mode)尝试访问这些页面时，会触发权限异常。

    3. 单页表的优势
    - 性能优势：
        - 用户态-内核态切换时不需要刷新TLB，因为页表不变
        - 系统调用、中断处理等不需要切换页表，减少了开销

    - 实现简单：
        - 只需要维护一套页表数据结构
        - 内核可以直接访问用户缓冲区，不需要额外拷贝

    - 内存效率：
        - 减少了页表本身的内存占用
        - 不需要为内核单独维护页表

    4. 双页表实现下的页表更换时机  
    在双页表（如KPTI）设计中：
        - 进入内核时：从用户页表切换到内核页表
        - 返回用户态时：从内核页表切换回用户页表
        - 进程切换时：在内核中切换到新进程的用户页表

    5. 单页表操作系统中的页表更换策略  
    如果设计单页表操作系统，我会选择在以下时机更换页表：
    - 主要时机：进程上下文切换时
    - 特殊情况
        - 创建新进程时：建立新的地址空间和页表
        - 进程退出时：销毁对应的页表
        - exec系统调用：完全替换进程的地址空间
